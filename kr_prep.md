# Подготовка к контрольной работе

## Когда выбрать rebase, а когда merge?

Rebase удобен для моей локальной feature-ветки: он переносит мои коммиты поверх обновлённой main и делает историю линейной. Merge подходит для общей ветки, с которой уже работают другие: он объединяет изменения без переписывания существующих коммитов.
## Что случится при rebase публичной ветки?

Rebase создаст новые версии коммитов с другими хешами. У коллег останется старая история этой ветки, поэтому при следующей синхронизации их изменения могут разойтись с моими. Им придётся вручную согласовывать историю, а повторное применение коммитов может вызвать конфликты.
## Зачем нужен multi-remote?

Multi-remote позволяет связать один локальный репозиторий с несколькими удалёнными. Например, команда может вести основной проект на GitHub и одновременно отправлять его копию на GitLab. Это полезно для зеркала проекта, миграции между сервисами или работы с разными командами.
